# Historical documentation index

As of 2026-09-10, the following retained documents are historical and
nonnormative:

- [`docs/superpowers/plans/`](../superpowers/plans/) — dated implementation
  plans;
- [`docs/superpowers/specs/`](../superpowers/specs/) — dated design and
  implementation specifications;
- [`.superpowers/sdd/`](../../.superpowers/sdd/) — historical task briefs,
  progress records, and worker reports;
- [`docs/design/`](../design/) — dated design directions and design plans;
- [`design-qa.md`](../../design-qa.md) and
  [`website/design-qa.md`](../../website/design-qa.md) — point-in-time visual
  QA records.

They remain in the repository because they preserve useful rationale,
tradeoffs, implementation intent, and evidence limitations. They do not define
the current product state, contributor workflow, supported features, release
status, or acceptance baseline. Current source, tests, public project
documentation, and explicit maintainer instructions take precedence.

Historical status labels such as “approved,” “passed,” “complete,” or
“accepted” apply only to the dated scope recorded in the individual document.
They must not be read as a current release or licensing claim. Paths expressed
with variables such as `$FLECK_REPO`, `$FLECK_MODEL_EVAL_DIR`,
`$PRIVATE_EVIDENCE_ROOT`, and `$OPTIONAL_TOOLING_ROOT` replace former
machine-specific locations; the underlying external artifacts are not part of
the repository and may no longer exist.

This index classifies the corpus centrally to avoid rewriting more than one
hundred meaningful historical documents with identical banners. Individual
files are changed only where privacy, portability, licensing, or factual
status requires a correction.
